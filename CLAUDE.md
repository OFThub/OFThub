# CLAUDE.md

GitHub profile repository (`OFThub/OFThub`). `README.md` is the public profile page; there is no application code, build, or test suite.

## Layout

- `README.md` — the profile page. Uses `<picture>` tags with `prefers-color-scheme` so each image has a `-dark` and `-light` variant.
- `assets/` — hand-built animated SVGs (hero, terminal, skills, projects, badges, commit-arcade, commit-arcade2) plus portrait GIFs. Always ship both `-dark` and `-light` files.
- `assets/metrics/` — generated by `.github/workflows/metrics.yml` (stats, languages, achievements, calendar). Do not hand-edit.
- `profile-3d-contrib/` — generated by `.github/workflows/profile-3d.yml`. Do not hand-edit.
- `.github/workflows/` — `metrics.yml` (daily 05:00 UTC), `profile-3d.yml` (daily 04:00 UTC), `contribution-games.yml` (every 6 h). All also run on `workflow_dispatch` and on push to `main`.
- `.remember/` — local session memory tooling; not project content.

## Conventions

- Contribution games (pacman, breakout, galaga, bomberman, puzzle-bobble, snake) are pushed to the `output` branch by `contribution-games.yml`. README image URLs must match the generated filenames exactly (e.g. `pacman-contribution-graph.svg`). Minesweeper is intentionally excluded: the action does not produce it.
- Workflow files use `secrets.METRICS_TOKEN || secrets.GITHUB_TOKEN`. The editor flags `METRICS_TOKEN` as an unknown context; this is a harmless linter warning.
- `lowlighter/metrics@v3.34` has no `config_theme` input; do not add it. Dark/light is handled by separate output files and the README `<picture>` tags.
- SVGs are XML: escape `&`, `<`, `>` in text content and validate with an XML parser after editing. When an element needs both a positioning `transform` attribute and a CSS animation, nest two `<g>` layers (CSS transforms override the attribute).
- Commits from the workflows are named `Update <path> - [Skip GitHub Action]`; keep manual commits distinguishable from them.
